# ArtDock Studio

平台与社区素材自动生产工作台

设计师输入一句话需求、选择素材包文件夹，工作台导入素材、根据完整 KV 选择 PSD 版式，并生成各资源位的成套预览。可逐尺寸微调背景、主标、副标、Logo、版权和按钮，技术质检与人工视觉审核通过后下载 ZIP。

## 在微光平台上运行（2026-10-30 改造）

工作台按微光平台《打包规范》和《开发者接入规范 V1》改成了平台应用（Node 服务，`weiguang.json` 声明 `database`）。打开工作台要先登录微光平台，并在应用的使用范围里。

**数据存在哪里**

- 项目、任务、素材库、规范中心、字体库都是全组共用一份，存在这个应用自己的 PostgreSQL 库里（平台给的 `DATABASE_URL`）。程序照旧读写容器里的 `data/runtime`，`platform/persistence.mjs` 启动时从库里恢复、之后把每次改动写回库；容器里的文件重新部署就清空，库才是保存处。
- 平台不备份任何数据。重要的成品请下载保存。
- 部署新版本时，新实例等旧实例把最后的改动存进库、交出写入权后才开始服务，期间页面显示“正在切换版本”，读取会自动重试，修改请稍后再点一次。
- 以前存在电脑上 `data/runtime` 里的数据不会自动搬上平台。

**画布生成（AI）**

- 用发起操作的同事自己的微光登录凭据调用微光画布，积分记在他自己的账号下；不再使用 `config/ai-huabu.json` 里的共用令牌。
- 每次提交前按这次的真实参数估价，在页面上确认“要花多少积分、余额多少”，取消或积分不够都不会提交、不扣积分。本次打开期间可以对同一模型选“不再询问”。
- 每次生成都归到项目选定的游戏：在「项目 › 编辑项目 › 归属游戏」从画布的游戏清单里选。项目没选游戏时生成会提示先去选，不会用默认游戏兜底。每位同事、每个游戏只建一张归属画布反复使用（画布被删或进回收站时会恢复或重建）。
- 生成任务在画布服务器上运行，关掉页面不会中断、积分照扣。工作台在后台查到任务结束；如果期间工作台重启，任务会标成“结果待确认”，同事回来点「继续查询」用他自己的凭据接着取回，不会重新提交。

**在你的电脑上计算的部分**

抠图、PSD 解析、扩图对齐、动效视频取帧和 GIF 编码原来在本机 Python 里做，现在在使用者自己的浏览器里做（服务器上不运行 Python）：

- 点了需要这些计算的操作后，右下角出现“正在你的电脑上计算”面板，显示正在做什么和真实进度，可以随时停止；停止或失败后可以重新开始。
- 计算时浏览器从工作台下载这一步的输入文件，算完把结果传回工作台；文件不会发到任何第三方。
- 第一次要下载运行库和模型，之后用浏览器缓存：Python 运行库（Pyodide 0.27.7，含 numpy、OpenCV、Pillow，约 30 MB）；遇到用渐变填充等效果的 PSD 再下载 scipy、scikit-image（约 40 MB）；人物识别 u2net（约 176 MB）；人物精细抠图 SAM2.1（编码约 138 MB、解码约 17 MB）。
- SAM2 编码模型用本机 GPU（WebGPU，一次约 0.3 秒，第一次编译约 4 秒）；没有 GPU 时用 CPU（约 15 秒）。u2net 和 SAM2 解码模型用 CPU。
- 需要新版 Chrome 或 Edge（支持 WebAssembly 和 Web Worker），建议 8 GB 以上内存。计算进行时请不要关闭页面；关掉页面后服务器最多等 10 分钟，没有页面接手就报错，可以重新打开后再试。
- 这一步要由发起操作的那位同事的页面来算：同一账号开着多个页面时由其中一个接手。
- 平台上没有 Windows 文字识别（OCR），动效的“文字保护”在平台上不生效；完整场景动效不受影响。

**字体**

- 公司字体库在「项目素材 › 添加项目常用字体」里可以在线导入字体文件（TTF、OTF、TTC、WOFF）。导入前要确认公司已获得授权；导入的字体全组共用，记下是谁导入的，只有导入的人能删除。
- 代码包只带开源的思源黑体、思源宋体（SIL OFL 1.1）；公司商用字体不打进代码包。

**平台上没有的本机功能**

- 粘贴本机文件夹路径导入素材：改成「选择素材包文件夹」，浏览器读出文件夹里的素材上传（最多 120 个 JPG、PNG、WebP、PSD、PSB）。
- 从 Windows 文件夹复制 PSD 后粘贴：在平台上请用“上传文件”或拖入。
- Photoshop 本机队列（`worker/`）、长图工坊原型（`longform-server.mjs`）不在平台版里。
- remove.bg 整体人物识别：要在应用「设置 › 环境变量」里填 `REMOVE_BG_API_KEY` 才能用，使用时会把图片发到 remove.bg；不填就只用浏览器里的 SAM2。

**打包和更新**

1. 第一次或运行库有变化时：`npm run prepare:browser-runtime`（按 `public/platform/runtime-manifest.json` 下载并核对运行库，复制 u2net、导出 SAM2；这些约 400 MB 的文件不进 Git）。
2. `npm run pack:platform`：检查运行库、投放尺寸表清单和密钥后，生成 `dist/平台与社区素材工作台.zip`。
3. 在微光平台「应用管理 → 新建应用」上传（已有应用在「版本」里上传新版本），检查通过后部署。部署后先在应用地址里走一遍主要流程，再上架。

## 本机开发

要求 Node.js 22。`npm ci` 安装依赖后：

```powershell
npm start
# 等同于 node platform/bootstrap.mjs --port 4173，打开 http://127.0.0.1:4173/（平台上不带 --port，用 3000）
```

- 不带 `DATABASE_URL` 时数据只存在本机 `data/runtime`，和以前一样。
- 要用微光账号（画布生成、项目的游戏清单），按《开发者接入规范 V1》第 6.3 节挡上平台的本机开发入口：`node weiguang-dev.mjs --app http://127.0.0.1:4173`，从 `http://127.0.0.1:4310/` 打开工作台。入口会启动本机 PostgreSQL 并显示 `DATABASE_URL`，带上它启动工作台就和平台上一样存进库。不要把登录凭据写进 `.env` 或配置文件。
- 本机计算同样在浏览器里做；`local-ai/` 下的 Python 环境只用于导出 SAM2 模型和对照测试。
- `npm test` 运行单元测试（测试用 `AI_HUABU_CONFIG` 指向模拟画布服务，只在 `node --test` 里生效）。

## 一套素材的生产流程

1. 在首页输入需求和本地素材包文件夹位置，点击“一键自动生成”。也可从“新建需求”逐步选择项目、业务线和资源位。
2. 素材包建议包含横/竖完整 KV、横/竖纯图背景、主标、副标、Logo、IP版权和按钮。纯图背景可以包含人物，但不应烘焙标题或 Logo。
3. 系统从横竖完整 KV 判断版式。每个资源位独立保存素材选择、焦点、缩放、位置和显隐；当前 PSD 版式没有要求的元素不会自动添加。
4. 在成套总览中检查各尺寸；按需调用智能扩图并微调。自动导入和本地生成不等于已授权后台批量调用付费 AI；扩图由设计师主动点击或明确授权测试。
5. 执行本地生成和技术质检。JPG、PNG 超限时压缩文件体积，保持目标像素尺寸。
6. 人工确认成套画面后完成任务并下载 ZIP。技术质检与视觉审核是两个独立环节，规则未核实的资源位不得正式交付。

## 规范中心与区域编辑

当前录入 20 个 PSD 资源位。左侧按业务线和渠道分类，中间显示资源位，右侧提供规则详情、规范图版本、使用记录和关联素材。

- “编辑区域”打开可视化编辑器，可切换 PSD 版式，拖动位置、拖动右下角缩放，或输入整数像素坐标。支持新增、删除区域，以及“仅当前版式 / 所有版式”范围。选中后方向键移动 1px，Shift + 方向键移动 10px。
- 保存前校验类型、画布边界和版本。不同资源位、不同版式独立保存；共享区域只作用于同一个资源位的所有版式。取消可放弃草稿，保存失败保留输入。
- 区域覆盖层保存在 data/runtime/layout-regions.json；原始 PSD 坐标基线 config/psd-layout-rules-v1.json 保留。修改区域后撤销该资源位的交付核实状态，须在“保存并发布规则”中重新核实并填写说明。
- 新建资源位默认禁止自动生产。编辑器可以为没有 PSD 的资源位补充默认版式坐标；仍须补全规范图、内容规则并核实，不能仅凭保存坐标自动开放生产。
- 37网游平台首页头图保持 1920×550、JPG、≤600KB、底部 85px 白色渐变；三个页面遮挡区作为规则保留，页面 UI 不进入成品。固定效果名称参与生产解释，修改时保留其含义。

规范图版本标签记录上传图片版本；区域保存版本用于防止多窗口覆盖，尚不是完整的区域历史回滚界面。

## AI 扩图

配置方法见 config/ai-huabu.example.json。复制为 config/ai-huabu.json 并在本机填写 Token，也可用 AI_HUABU_CONFIG 指定私有配置路径。不要输出 Token。

默认 Nano Banana Pro（banana_pro），调用或对齐检查失败后回退 RH 定向扩图（rh_image_outpaint）；可手动选择 RH。目标最长边超过 1600px 时请求 4K，其余请求 2K。模型返回尺寸不等于最终交付尺寸，导出仍按资源位规范处理。

每次扩图仅发送当前原始背景图。重试始终取原始素材，不加工旧扩图。固定提示词保护原图曝光、明暗、色彩和主体，新增区域默认只允许环境，禁止新增/复制人物、生物、文字、Logo、版权、水印和 UI；仅显式开启“允许新增主体”才放宽主体限制。

Nano 原始结果不能保证人物像素不变。当前新增本地 SIFT 特征对齐，定位原图在生成结果中的位置，再使用遮罩让人物区域来自原始 KV，并让 AI 环境与它使用同一套缩放、位移。该步骤使用现有 local-ai/.venv 中的 OpenCV，不发送额外素材；其不可用、匹配不可靠或扩展范围不足时，Nano 结果不作为成功输出，按既有顺序尝试 RH。图像内容仍需人工验收，几何对齐通过不等于没有新增主体。

再次缩小时可能超出已生成范围；画布提示范围不足，并阻止导出该成品。旧 Nano 结果缺少对齐信息时仍需人工检查；新逻辑不会自动改写已完成任务或已交付文件。

原图保护指同样缩放条件下的源图像素，不代表跨分辨率完全没有重采样；最终 JPG 编码和 PSD 固定渐变也会改变像素。对齐和遮罩不使用人物模糊或整图调色来隐藏接缝。未配置、禁用或全部调用失败时保留当前版本并显示失败；禁止镜像、拉伸、模糊填充冒充成功扩图。

## 渠道资源位逐稿制作

在“渠道发行业务 → 渠道资源位”选中交付稿，点击“进入制作工作台”。上方可随时切换资源位尺寸；左侧同尺寸多稿独立管理，图层与草稿分别保存。

- “文字”创建可编辑文字层；“图片”导入 Logo、人物等独立素材，可拖动、调整位置和宽度。合成图中的人物不会自动变为透明图层。
- “文案重制”可上传或裁取原稿字效，输入准确的新文案，显式点击后由现有画布图像服务生成 3 版候选。候选仅作为参考；透明底提取成功后须逐字核对才能采用。若模型写错字或提取失败，可用“准确文字重绘”生成白金字效的可编辑文字层。
- “背景扩图”按当前交付稿设置原图占比，在外围生成环境背景。原图不覆盖，候选采用前需检查画风、接缝、清晰度和旧文案是否已烘焙在底图。点击生成会将所选图像发送到已配置的外部服务并消耗额度。
- “生成交付候选”按该稿要求的像素尺寸、格式和体积保存新版本；超限时只在保持清晰度的条件下优化，不能满足则明确失败。PSD 场景预览和人工渠道验收仍按原流程进行。

渠道编辑数据在 `data/runtime/channel-resource-overlays.json`，上传素材与 AI 候选在 `data/runtime/storage/channel-resources-*/editor/`。图像模型可能写错中文或忽略背景颜色要求；系统不自动宣称文字准确，也不会在失败时覆盖原稿。

## 社区与外媒母版

社区外媒完整母版生成会先创建画布，并在方向、场景、标题等步骤共用同一 `canvas_id`。各阶段保存服务任务编号和原始返回图片，生成失败不替换当前母版。旧的图片提交入口也会在缺少画布编号时先创建画布，再提交生成。

当设计师明确要求“使用图2角色”，且没有另行绑定透明角色素材时，系统从指定的角色设定参考中创作同一位角色，保留在场景插画中；三视图不会被当成三个人物。主标题和 Logo 仍独立合成。后续背景修改会保留这种场景里的角色；已经上传独立角色素材的任务沿用原有分层流程。

“AI 创作 → 生成插画”的新提交采用 `layered-illustration-v1`：一次提交管理配套角色、纯场景背景及本地组合预览。角色方式为按主题设计动作、指定动作、原样使用；原样使用要求上传真实透明角色 PNG，直接复用可见原像素，不重绘。主题/指定动作先生成独立角色，再把实际角色和本地摆位示意作为内部参考生成无人物背景，界面参考图编号保持不变。角色优先接受原生透明通道，也支持经校验的纯色底转透明；不合格的透明、空图或边缘裁切结果保留原始文件并明确失败，不自动追加付费生成。

背景与角色成功后作为一套素材入库并自动组合，可独立拖动、缩放、修边和下载。纯背景、角色、文案及组合有各自预览，选择旧背景会恢复对应角色；历史整图与已交付任务不自动改写。各生成阶段保存独立幂等键、服务回执、原始返回图及文件摘要，刷新只查询原任务，继续处理复用已完成步骤。若生成期间画面被手动修改，新素材只入库。动作生成通常调用两次图片服务；原样角色仅调用背景生成。当前实现以一个角色和一个背景为一套，多角色遮挡和独立接触阴影尚未扩展。

本地验证：`node --test test/community-layered-illustration.test.mjs test/community-materials.test.mjs test/community-object-layers.test.mjs`；`node scripts/verify-layered-illustration-ui-20261026.mjs` 启动隔离工作台、本机模拟图片服务与隐藏浏览器，验证一次提交、刷新恢复、独立拖动/缩放及下载，不使用真实服务额度。真实画风、动作和透明边缘仍需样例视觉验收。

相关验证：`node --test test/ai-huabu.test.mjs test/ai-huabu-submission.test.mjs test/community-ai-generation.test.mjs test/community-banner-design.test.mjs test/community-banner-session.test.mjs`。`node scripts/verify-community-canvas-local-20261020.mjs` 使用隔离任务副本和本机模拟服务，不发送外部素材、不使用额度。`node scripts/verify-community-canvas-live-20261020.mjs --generate` 才会调用真实配置的画布服务，执行前需要对应授权；已有回执只查询原任务。

## 投放资源位

在“投放业务 → 投放资源位”查看 `02 规范与模板/投放/资源位规范/投放资源位尺寸表.xlsx` 的“投放资源位”工作表。工作台只使用这一张工作表当前的 10 项 JPG 交付要求；同工作簿的其他工作表不参与制作或验收。服务会在该表要求或参考图修改后更新规范版本；参考图仅作对照，不当成自动生成的交付成品。历史 GIF 保留，不自动加入当前交付清单。

新建投放任务后，可以粘贴或上传主视觉和独立 Logo，在 JPG 稿中调整构图与 Logo 大小、位置，再生成候选；也可上传已经制作完成的 JPG。B站两侧 40px 保护区仅作为预览标记，不进入导出画面。

右侧“AI 修改”支持当前静态图片：输入“人物大一点，标题分成两行，保持原色调”等要求，点击“生成修改稿”调用现有画布 Nano Banana Pro；这会使用画布账号额度，不依赖 Codex 会话。只修改当前尺寸，并创建未审核的新候选，不覆盖历史候选。生成完成后可“查看修改前”或“撤回本次修改”。独立 Logo 保留在本地合成，支持“Logo 放大20%”“Logo 移到右上角”；仅调整 Logo 大小、位置时不调用付费模型。无 Logo 规范不能被输入要求覆盖。

AI 修改使用后端 `config/ai-huabu.json` 或 `AI_HUABU_CONFIG` 指定的私有配置，凭据不会发送到浏览器。新请求先核对画布模型目录，选择可用的 Nano 原生通道；无可用原生通道时在付费提交前报错，不自动切换到中转别名。任务、请求编号、画布回执和修改前草稿持久化保存；页面刷新只查询任务，已有画布编号可在服务重启后继续取回。结果未确认时显示“继续查询”，同次提交复用幂等键，不自动另开付费任务；超过幂等查询时限时要求管理员核对。生成期间锁定当前稿件，其他尺寸仍可查看。结果的尺寸、比例、格式和体积通过校验后才入库，视觉效果仍须人工检查。

明确要求“重新排版”或减少大面积留白时，使用整体重排指令，允许移动、放大和分区安排原有信息；局部修改则保留其他区域。独立 Logo 的真实叠加区域作为构图约束传给模型。对整图重排结果检查粗略结构变化：近似原图、仅改明暗或丢失主要结构时保留结果文件并显示未达要求，不替换当前候选，也不自动追加付费重试。这项检查仅用于拦截明显未重排，不能代替视觉审核。回执保存实际提示词和幂等键，代码升级后查询原任务继续复用原提交。

制作工具不再显示“画面素材”“任务 Logo”下拉框或 Nano 重新构图说明。保留更换源图、更换 Logo 和大小、位置调整；当前素材关联由任务草稿与 AI 修改结果自动维护。

AI 修改按 Gemini 原生画幅提交；640×400 使用临时 3:2 画幅，生成后等比取回原交付矩形，不通过横纵拉伸凑尺寸。原始返回图先保存，再做比例和交付检查；失败时可“重新处理已有结果”，复用原图或原画布任务，不重新计费。旧 8:5 请求返回 3:2 时支持有界的等比恢复。明确点击重新生成会使用新请求编号，避免同一句要求永久复用旧失败回执；网络回执未知时仍复用原编号查询。

“修复顶部接缝”“修复左侧拼接”等方向明确的背景修复，使用完整场景输入并遮罩待修边缘；只采用修复区和短的平滑过渡，其他区域保留原图。默认修复沿边约6%，也可明确输入“顶部10%”或“顶部40像素”。含人物缩放、文字改排等混合要求时，继续使用完整画面修改，不能静默忽略其它要求。未补齐遮罩、没有变化时保留旧稿并提示未达要求。

如果目录重新启用 GIF 资源位，动效使用微光画布可灵 V3（`kling_v3`），按原画意境制作完整场景微动，文字可由原生透明图层本地合成；不使用小块场景硬拼或通用放大缩小替代场景判断。`lib/ad-kling-motion.mjs` 管理模型、动作指令和持久收据；`lib/ad-video-motion.mjs` 将真实视频转为 640×400、10 帧、1 秒循环 GIF，保持小于700KB。当前“AI 修改”输入器只改静态图，不改变既有 GIF 制作规则。

视频生成在后台进行，页面显示保存的进度；刷新仅查询原任务，不另提交。模型返回几乎静止的画面、移动镜头或转码不达标时明确失败，保留视频及旧候选；旧稿不能冒充本次完成。编码失败可复用视频重新转换，明确“重新生成动效”才创建新模型任务；提交结果未知时只查询已有编号。已有同源动图调整构图可本地重排，不重复调用模型。候选入库检查格式、像素尺寸和体积限制；Logo、文字、人物及安全区仍需人工逐项确认。完成当前清单所有稿件后可成套下载 ZIP。

尺寸表解析脚本为 `scripts/sync-ad-resources.py`；结构化清单保存于 `config/ad-resources-v1.json`，本地任务及候选保存在 `data/runtime/ad-resources-jobs.json` 和 `data/runtime/storage/ad-resources-*/`。表中“无”体积限制按未给出上限处理，不能推断为平台永远无限制。

## Photoshop 与当前边界

worker/ 保留 Photoshop 本机队列和 ExtendScript 适配器。按 worker/templates/README.md 配置真实 PSD 图层，并由 worker/config.example.json 建立本机配置后运行 node worker/agent.mjs；只准备任务包可加 --once --prepare-only。

浏览器生产链可独立运行；Photoshop 链路仍需真实模板和本机 Photoshop 联调。当前不支持合并主视觉中的人物自动重排、肢体补全或自动判定视觉审核通过。投放资源位的 GIF 已接入上述可灵 V3 默认生成流程；专题和效果数据统计不在当前范围内。长图使用下方独立原型入口。
